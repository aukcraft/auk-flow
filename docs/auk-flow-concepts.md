## 0. 项目定义

**auk-flow：PC 优先的拟人化自动化引擎。**

一句话：**不造"另一个按键精灵"，造"按键精灵做不到的那一半"**——按键精灵生态已覆盖"能不能自动化"（找图/找色/OCR/模拟点击），auk-flow 的核心差异是**行为拟人化**（轨迹生成、时序建模、per-user 个性化）与**现代架构**（状态机可视化、行为树编排、可观测面板）。

定位边界：

- 通用桌面自动化 + 自动化测试工具（买家是防守方：游戏厂商安全团队、反欺诈厂商、软件测试团队）
- 非目标：游戏对抗场景、薅羊毛、抢购工具售卖——产品形态、宣传话术、功能清单中均不出现

## 1. 法律边界（核心约束层）

### 1.1 "工具 vs 外挂"的判定标准（司法实践视角）

法院不看口头定位，看客观行为组合：

1. **功能专门性**：脱离游戏是否失去存在意义（驱动级输入/轨迹拟人在办公场景是冗余设计）
2. **宣传话术**："防封/过检测/对抗性质"写进官网 = 主观故意证据
3. **生态指向性**：游戏脚本市场、按游戏分类模板、客服答复记录

### 1.2 平台责任边界

- "平台+用户脚本"模式不构成免责（蜂窝/触动精灵判例：高管仍被判刑）
- 开源核心引擎 + 企业版分层（Kali 模式）：核心库开源建立"公开安全技术"认知，企业版（靶场/评估报告/B2B 服务）闭源收费
- 客户准入：企业实名 + 合同授权条款；个人版仅开放内置靶场（模拟环境自测）
- 工具外流不可避免 → B2B 合同、授权审计、不接个人客户

### 1.3 Issue/社区处理策略

- ❌ 错误：评论"关于外挂开发已关闭"→ 承认定性 + 受理换皮 = "明知+放任"书面证据
- ✅ 正确：**永不识别、永不定性、只支持功能**。过滤发生在格式层（issue 模板引导技术化表述："检测框偏移 N 像素"而非"打怪时"），不是道德层
- 配套：USAGE_POLICY.md 书面政策 + 模板引导 + 对 PR 中游戏专门化内容必须拒绝（功能层红线 > 话术层红线）

### 1.4 场景风险光谱（产品默认模板与运营红线）

| 场景 | 风险 | 边界 |
| --- | --- | --- |
| 自用非竞技脚本（如 MMO 寻路） | 法律≈0，账号封禁风险可控 | 不盈利、不传播、不碰打金 |
| 移动端便利 skills（如下单/签到） | 白色 | 不做薅羊毛、不卖抢购工具、不多账号批量 |
| 抢购工具**售卖** | 高危（12306 判例） | 自用可以 |
| 薅羊毛自动化 | 黑色（诈骗罪判例） | 不碰 |
| 游戏外挂平台 | 黑色 | 产品形态上不出现 |

### 1.5 行为生物特征合规

per-user 个性化适配文件 = 行为生物特征（同指纹/声纹），按敏感个人信息对待：本地加密存储、TLS 传输、可一键删除、不做跨账号比对。

## 3. 架构设计

### 3.1 仓库结构（PC 优先，向 auk-take 的工程约定对齐）

```
auk-flow/
├── packages/
│   ├── core/          # 纯 TS: AHK 解析、意图 IR、humanize pass、配置、校验（不碰 RN/Tauri）
│   ├── ui/            # RN 原语组件（View/Text/Pressable），PC 经 RNW 跑 Tauri webview
│   ├── desktop/       # Tauri 2.x + RNW 壳
│   ├── engine/        # Rust workspace: 截屏 / 输入执行 / ONNX 推理
│   └── plugin-core/   # 按 auk-plugin-spec 暴露 engine 能力 → UI
└── docs/
```

### 3.2 关键决策：三层区别对待

1. **工程结构**：`packages/*` monorepo、core 纯逻辑包、plugin-core 边界——完全对齐 auk-take 约定
2. **UI 组件层（核心动作）**：第一天用 RN 原语写，经 react-native-web 跑 Tauri webview → 未来移动端零翻译成本。代价：放弃 shadcn/ui，样式能力略糙（监控面板可接受）
3. **引擎层**：无论 UI 怎么选，都是 Rust——无冲突

**里程碑闸门**：RNW+Tauri 链路（Metro/打包/invoke）设 **2 周时间盒**，不通则 `ui` 包降级 target 到普通 React DOM，损失只限于 shell 包。

### 3.3 引擎层（进程内，无 sidecar）

- 截屏：Rust crate（screenshots / DXGI）
- 输入：windows-rs SendInput / enigo，动作队列毫秒级时序
- 模型推理：**`ort`（ONNX Runtime Rust）**，Python 降级为纯训练工具 → 训练/推理分离
- UI↔引擎：Tauri invoke / emit，零进程间通信

### 3.4 未来移动端预埋（只记录，不实施）

- 触摸 vs 鼠标：无 hover；接触即开始、抬起即结束；边缘强制减速
- 数据通道升级：`[dt, dx, dy]` → `[dt, dx, dy, pressure, area, orientation]`（风控看压力渐强渐弱曲线）
- 录制必须原生 Android（MotionEvent），浏览器拿不到压力——录制 App 顺路成为产品"标定工具"
- 对抗方转移：游戏反作弊 → 金融级行为生物识别（支付宝/银行风控）

### 3.5 插件体系（auk-flow 消费方）

auk-flow 是 auk-plugin-spec 的 PC 宿主（插件形态：Rust crate + Rhai/JS 脚本，skills 即插件）。
spec 五要素：manifest / schema（参数声明→自动生成 UI）/ lifecycle / events / host API。

## 4. 核心技术设计

### 4.1 四层架构

```
感知层  截屏 → 检测（V1 模板匹配；后续 YOLO nano + OCR）→ 结构化世界状态
思考层  有限状态机 + 行为树（节点积木: 条件/动作/序列/选择）
        ← 不依赖大模型; 0.5B 级模型只做低频语义规划(任务文本→目标队列)
执行层  Rust 动作队列: 上层发"意图"(combo_burst), Rust 执行带毫秒时序的键位序列
监控层  Tauri 面板: 截图+检测框叠加 / 状态机实时高亮 / 日志 / 参数调节
```

关键设计：**意图与操作分离**——上层只发"什么时候放什么技能"，连招键位/时序是可配置资产（如 `COMBO_BURST: [{key:"1",press:0,release:50},...]`）

### 4.2 输入模拟路线（明确不做驱动级）

内核驱动 = KDF 开发 + 签名成本 + Win11 HVCI 冲突。
优先级：V1 软件模拟 → V2 Rust 执行层提时序 → V3 行为随机化（比驱动级更有效：驱动级解决"输入来源"，行为检测解决"像不像人"）

### 4.3 UI 面板核心交互

1. **检测框叠加**：bbox 随帧下发，canvas 画框+置信度，调阈值肉眼可见
2. **状态机实时高亮**：切换时节点闪烁，滞留超 N 秒标黄（一眼看出 bot 卡住）
3. **行为参数拖拽**：行为树叶子配置拖拽排序，不写代码调策略
4. 消息信封统一：`frame` / `state(from,to,reason,ts)` / `log(level,msg)`；`reason` 字段是排查异常的钥匙

## 5. 拟人化引擎（项目核心 ML）

### 5.1 PC 鼠标运动学

- **WindMouse**：重力+风+阻尼物理模拟，自带过冲-回调（"大致瞄准+微调"），几十行代码
- **最小急动度模型**（Flash & Hogan 1985）：人手自然运动的理论解 = 五次多项式，速度剖面钟形
- **Fitts 定律**控时序：T = a + b·log₂(D/W+1)；bot 最大破绽是时长分布恒定
- 两阶段结构：弹道(快速接近) + 校正(过冲回调/微调) + 点击前 80-300ms 犹豫

### 5.2 检测方视角（知己知彼）

鼠标事件 100-1000Hz 上报，逐帧算速度/曲率/角度与真人分布对比；直线匀速 = 最大红旗。

### 5.3 运动原语与操作语义解耦（关键抽象）

**模型只负责"像人一样从 A 到 B 到 C"，终点是按钮还是图标由上层状态机决定** → 跨场景复用的根基。

### 5.4 连续 vs 离散

- 连续曲线（8字/波浪线/拖动）：最小急动度样条插值途经点 + 风格层（漂移/微颤/速度剖面重采样）。形状零误差，模型只学风格残差，数据需求降到 1/5
- 离散多点（连点）：拆段生成，段间停顿才是拟人特征（200-600ms 视线转移，服从 Fitts）
- 标定盲区：纯 8 字学不到目标获取行为 → 标定必须含"随机点点击"60 秒

### 5.5 反直觉风险：稳定像 A = 固定指纹

真人风格会漂移（疲劳/心情/设备），方差极小的账号本身是异常。
对策：学**分布**不学均值；输出头预测 μ/σ（高斯）；推理时 sampling + temperature；检验标准"周一和周五的轨迹混在一起分不出来"。

## 6. 数据与训练

### 6.1 采集

- HTML recorder（随机红点，点击保存），合并格式 `[[t,x,y],...]`（相对毫秒，起点为 0）
- 多点任务录制可拆段 ×3 效率（300 条 → 900 段）
- 剔除脏数据（停顿>2s、切窗、分心）> 数量
- 移动端预留：原生 MotionEvent 录制 App（兼作产品标定工具）

### 6.2 数据量

| 用途 | 条数 |
| --- | --- |
| 过拟合验证 | 50 |
| base 模型 | 500~2000（15~40 分钟录制） |
| per-user 个性化 | 300~500 |
| 标定手势 | 每种 10~20 次（2 分钟） |
| 5000+ 收益递减（瓶颈是模型表达力不是数据） | |

### 6.3 输入输出协议

```
输入: [cosθ, sinθ, log₂D, T, mode]   θ=方向角 D=距离 T=总时长预算 mode=连续/离散
      （不用绝对像素 → 与分辨率解耦; 不用裸角度 → cos/sin 连续无跳变）
输出: [dt, dx, dy] 逐步增量(不输出绝对坐标, 误差不累积, EOS=位移≈0且dt拉长)
      移动端预留 [pressure, area, orientation]
推理: 条件 → 逐步采样(勿取μ!) → 累积 → Rust 按时序派发
条件向量 v2 扩展: ⊕ user_embed[64] ⊕ context[k]
```

### 6.4 训练（V3 范畴）

- 30~50 万参数单层 LSTM；输出 4 维（μ_x, μ_y, σ_x, σ_y）+ **NLL 损失**（学分布的关键）
- Colab T4：3~8 分钟；本地 CPU：~30 分钟
- 先 50 条过拟合验证管线（坐标归一化/时间戳转速度/padding），再全量
- 变长序列：插值到定长 128 点（新手友好）或 pack_padded_sequence
- 导出 ONNX → ort 推理；PyTorch 训练，TF 不用
- 风格档位用 embedding/one-hot（连续整数会被当成可平均的数值）

### 6.5 评估

生成 vs 真迹对比：速度剖面、曲率分布、总时长分布、双端数据互相印证（同用户 PC+手机行为特征一致 → 身份验证加分项）；判别器检验 AUC≈0.5。

## 7. 个性化体系（三段接力）

```
冷启动: 2分钟标定(手势60s+目标点击60s) → 参数拟合(零训练, scipy反解WindMouse参数分布)
使用中: 真实轨迹静默累积(授权后)
接管:   数据够了 → 个性化微调, 参数拟合降级兜底
```

- LoRA 适用前提：base ≥ 0.5B；小模型直接全量微调（几 MB，秒级）
- 单人工具不需要 LoRA；多人产品冷启动可评估
- 更新机制：定期重训 + EMA 平滑防单次污染 + 版本回滚
- 进阶：标定参数可作微调初始化，两段式衔接

### 数据规模现实校验

训练 10~60 分钟 ≠ 项目周期：录数据 2~4h、清洗标注 2~3h、调参对比 2~5h（无限黑洞）才是成本。建议：先 WindMouse+Fitts+过冲组合上线，录数据训练留作 V3。

## 8. DSL 决策（2026-09-16 追加）

**v1 DSL 原型 = AutoHotkey v1 语法子集 + `;/* auk: */` 注释指令扩展。**

- 存量生态冷启动；脚本在真 AutoHotkey 中保持合法（双向兼容、可导出、不锁用户）
- 子集白名单：`Click/MouseClick/MouseMove`、`Sleep`、`ImageSearch/PixelSearch/PixelGetColor`、`Send/SendInput`、`WinActive/WinWait`、`Loop/While/If/Break`、`#IfWinActive`；**排除 DllCall/COM/文件写入**
- 编排策略（stuck/疲劳节律）下沉引擎层全局配置，不进语法
- AHK → AST（core TS）→ 意图 IR → humanize pass → Rust 动作队列
- 三层坐标：L1 锚定 / L2 物理像素（DPI/多显/误差累积舍入）/ L3 归一化模型空间

## 9. 数据合规决策（2026-09-16 追加）

- 三级合规架构：L1 实时流过不落盘 / L2 落盘真匿名（单条轨迹无 ID 不聚合）/ L3 上传需单独 opt-in
- 鼠标轨迹具"操作声纹"可识别性 → 假名聚合即个人信息，匿名必须彻底
- v1 产品全部 L1/L2 处理（本地拟合 + 即用即弃）→ 零同意弹窗
- 年龄：招募分层配额 + 每条轨迹只带 5~10 年区间标签 + 无 ID 不聚合；14 岁以下不采集
- per-user 适配文件按敏感个人信息对待（本地加密、可删除、不跨账号比对）

## 10. 版本路线

```
V1: 截屏 → 模板检测 → WindMouse 单次移动点击闭环（纯规则，零训练）
V2: Rust 执行层 + 2 分钟标定系统（参数拟合个性化）
V3: 个性化模型（有真实用户数据后）
```

## 11. 核心设计观点存档

- 轮子存在 ≠ 没价值；学"形状+风格"拆分比端到端 NN 更省数据
- 运动原语与操作语义解耦：模型只管"像人一样 A→B→C"，不管具体干什么
- "对抗性质自动化"的正确出路：买家换成防守方（测试工具），同一套技术法律性质翻转
- "平台不做外挂"不构成免责；法院看客观行为组合；功能层专门化比话术层危险一万倍
- issue 换皮受理直觉正确，但"识别+定性+配合换皮"三连是证据自杀，改为"从不识别、只支持功能"
- 移动端便利 skills 自用+公开通用引擎 = 风险最低路线
- UI 第一天用 RN 原语写，是给未来移动端买保险的核心动作
- 拟人化的必要性取决于"是否存在检测方"：有对抗才需要，纯效率自动化越快越好
- 稳定像 A 反而是固定指纹——学分布不学均值
